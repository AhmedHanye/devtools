This guide shows you how to configure and start the DevTools loopback daemon with custom network bindings, resolve port conflicts, and mount alternative static asset directories.

## Prerequisites

Ensure you have completed the following prerequisites:

- DevTools workspace dependencies are installed (`bun install`).
- Frontend assets are compiled (`bun --filter @devtools/frontend build`).

## Start daemon on the default port

To run the daemon with default settings, execute the `web` command through Bun.

```bash
bun run devtools web
```

By default, the daemon binds to `127.0.0.1` on port `4000` and serves static files from `apps/frontend/dist`.

## Bind custom port and host

You can customize the listening port and network interface using command line options or environment variables.

### Using CLI options

Pass the `-p` or `--port` flag to change the port, and `-H` or `--host` to specify the host address.

```bash
bun run devtools web --port 5050 --host 127.0.0.1
```

### Using environment variables

The daemon inspects `PORT` and `HOST` if corresponding command flags are omitted.

```bash
PORT=5050 HOST=127.0.0.1 bun run devtools web
```

> [!NOTE]
> For security reasons, the daemon restricts origins and network bindings to loopback interfaces (`127.0.0.1` or `localhost`). Binding to public network interfaces is prohibited by the loopback security boundary.

## Resolve port conflicts

When the requested port is already occupied by another process, DevTools handles the collision based on terminal interactivity.

### Interactive shell resolution

In an interactive terminal session (TTY), the CLI scans sequential port numbers starting at the target port, identifies the first free socket, and prompts for confirmation:

```text
? Port 4000 is in use. Would you like to use available port 4001 instead? (Y/n)
```

Pressing `Enter` automatically binds the daemon to the suggested alternate port. If you decline with `n`, the process halts with exit code 1.

### Automated or CI environments

In automated pipelines or scripts where `stdin` is not an interactive terminal, the daemon prints an error message and terminates immediately:

```text
Port 4000 is already in use. Use --port <port> or set PORT=<port> to specify a different port.
```

To avoid build failures in non-interactive environments, assign an explicit open port or pass `PORT=0` to let the operating system assign an ephemeral port.

## Serve custom static directory

When developing alternative web dashboards or running embedded documentation previews, point the daemon to a custom static directory using `--static-dir` or `-s`.

```bash
bun run devtools web --static-dir ./custom-dashboard
```

Alternatively, define the `DEVTOOLS_STATIC_DIR` environment variable:

```bash
DEVTOOLS_STATIC_DIR=./custom-dashboard bun run devtools web
```

The daemon verifies that the specified directory exists before starting. If the path does not exist, startup terminates with an informative error:

```text
Static assets directory not found at "/path/to/custom-dashboard". Run "bun run build" in @devtools/frontend to generate static assets, or pass --static-dir <path>.
```

## Verification

Confirm that your daemon instance is serving requests properly by inspecting the health route with cURL.

```bash
curl -I http://127.0.0.1:4000/api/health
```

Expected HTTP response headers:

```text
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Access-Control-Allow-Origin: 127.0.0.1
Content-Length: 95
```

Verify that static HTML assets are also returned correctly from the root path:

```bash
curl -I http://127.0.0.1:4000/
```

The response should return HTTP 200 with `Content-Type: text/html`.
